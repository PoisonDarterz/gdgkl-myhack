# Quick Plan: Login + Dashboard + Run Judge Page

## Task 1 — Supabase SSR setup + install deps

**Files:**
- `src/lib/supabase/client.ts` — browser Supabase client (createBrowserClient from @supabase/ssr)
- `src/lib/supabase/server.ts` — server Supabase client (createServerClient from @supabase/ssr)

**Action:**
1. Run `npm install` in project root to install existing deps
2. Run `npm install @supabase/ssr` to add SSR package
3. Create `src/lib/supabase/client.ts` with `createBrowserClient`
4. Create `src/lib/supabase/server.ts` with `createServerClient` (reads cookies from Next.js headers)

**Why:** @supabase/ssr is required for session cookie handling in Next.js middleware and server components

**Verify:** `src/lib/supabase/client.ts` and `server.ts` exist; `@supabase/ssr` in node_modules

## Task 2 — Middleware + Login page

**Files:**
- `middleware.ts` (project root)
- `app/login/page.tsx`

**Action:**

`middleware.ts`:
- Use `createServerClient` from @supabase/ssr with cookie helpers from next/server
- Protect `/dashboard` routes: if no session, redirect to `/login`
- Refresh session cookie on every request
- Matcher: `['/dashboard/:path*']`

`app/login/page.tsx`:
- Client component
- Email + password form using `supabase.auth.signInWithPassword`
- On success, `router.push('/dashboard/judge')`
- On error, show inline error message
- Styled consistent with existing site design (bg-[#F5F5F5], font-mono, black/white buttons)
- No registration needed (admin-only)

**Verify:** `/login` page renders; unauthenticated access to `/dashboard/judge` redirects to `/login`

## Task 3 — Dashboard layout + Judge page

**Files:**
- `app/dashboard/layout.tsx`
- `app/dashboard/page.tsx`
- `app/dashboard/judge/page.tsx`

**Action:**

`app/dashboard/layout.tsx`:
- Server component
- Read session via server Supabase client
- Render children with a minimal nav bar (Sign Out button that calls `supabase.auth.signOut()` then redirects to `/login`)

`app/dashboard/page.tsx`:
- Redirect to `/dashboard/judge` immediately

`app/dashboard/judge/page.tsx` — client component with this structure:

**Section 1: Sheet Input**
- Text input for Google Sheet URL
- "Load Sheet" button — fetches CSV via `getPublicGsheetCsv` helper, parses it, extracts team rows (col index 10 = team name)
- Validate: show error if URL is empty or fetch fails

**Section 2: Sheet Visualizer (table)**
- Rendered after successful load
- Columns shown: #, Team Name (col 10), GitHub (col 6), Docs (col 8), Status, Score, Actions
- Each row has a status badge: `pending | running | done | error`
- Each completed row shows score and "View Details" button

**Section 3: Run Controls**
- "Run All" button — disables when running; iterates teams sequentially:
  ```
  for each team:
    set row status to "running"
    POST to Supabase Edge Function judge with { sheet_url, team_name }
    await response
    fetch result from evaluations table (filter by project_title = team_name, latest)
    set row status to "done", store result
    set row score from final_score
  ```
- Show overall progress: "Evaluating team X of N..."
- Each team can also be run individually via a "Run" button in its row

**Section 4: Detail Modal**
- Triggered by "View Details" button on any done row
- Shows full evaluation breakdown:
  - Executive summary
  - Final score + head judge verdict
  - BA findings (verdict, strengths, risks, scores)
  - AI SE findings (verdict, strengths, vulnerabilities, scores)
  - Category scores table
- Close button (X) and backdrop click to dismiss

**Styling:** Consistent with existing admin page — bg-white cards, border-black/10, font-mono, rounded-2xl

**Verify:**
- Sheet loads and shows team table after URL input
- Run All iterates teams and updates status badges in real time
- Detail modal opens with evaluation data after run completes
