The existing `globals.css` already has an `@theme inline` block wiring shadcn CSS variables to Tailwind. The font variables slot in alongside existing entries.

**Confidence: HIGH** — confirmed via official Tailwind v4 upgrade docs and official Next.js font+Tailwind integration docs. The `@theme inline` block in `globals.css` is exactly the right place.

## Implementation — Exact Code Patterns

### layout.tsx — Font Loading

```typescript
import { Courier_Prime, Instrument_Serif, Workbench } from 'next/font/google'

const courierPrime = Courier_Prime({
  weight: ['400', '700'],
  style: ['normal', 'italic'],
  subsets: ['latin'],
  display: 'swap',
  variable: '--font-courier-prime',
})

const instrumentSerif = Instrument_Serif({
  weight: ['400'],
  style: ['normal', 'italic'],
  subsets: ['latin'],
  display: 'swap',
  variable: '--font-instrument-serif',
})

const workbench = Workbench({
  subsets: ['latin'],
  display: 'swap',
  variable: '--font-workbench',
})
```

Apply to `<html>`:
```tsx
<html
  lang="en"
  className={`${courierPrime.variable} ${instrumentSerif.variable} ${workbench.variable} antialiased`}
>
```

**Why this approach over `.className`:** Using `.variable` + CSS custom properties allows the fonts to be referenced anywhere in CSS (including `globals.css` `@theme inline` block and arbitrary Tailwind values). Using `.className` directly on `<html>` would only set one font as the default and make it harder to apply different fonts per component.

**Why `display: 'swap'`:** Prevents invisible text during font load. The design has dense text sections; swap ensures content is readable immediately with a fallback font, then switches to the custom font. This is the recommended value for content-heavy text.

### globals.css — Tailwind v4 @theme Integration

Add inside the existing `@theme inline` block:
```css
@theme inline {
  /* ... existing shadcn tokens ... */
  --font-mono: var(--font-courier-prime);
  --font-serif: var(--font-instrument-serif);
  --font-display: var(--font-workbench);
}
```

Override shadcn color tokens in `:root` to match design:
```css
:root {
  /* ... existing shadcn vars ... */
  --background: #F5F5F5;
  --foreground: #282828;
  --muted-foreground: #5C5C5C;
}
```

**Note:** shadcn uses oklch values by default. Overriding with hex values works in modern browsers. Alternatively convert: `#F5F5F5` ≈ `oklch(0.961 0 0)`, `#282828` ≈ `oklch(0.178 0 0)`, `#5C5C5C` ≈ `oklch(0.408 0 0)`. Using hex is simpler and more readable for design handoff.

### Marquee — Pure CSS Pattern

In `globals.css`:
```css
@keyframes marquee {
  from { transform: translateX(0); }
  to { transform: translateX(-50%); }
}

.marquee-track {
  animation: marquee 12s linear infinite;
  white-space: nowrap;
  display: flex;
}
```

In JSX — duplicate the text to create seamless loop:
```tsx
<div className="overflow-hidden">
  <div className="marquee-track">
    <span>REGISTER NOW &nbsp;&nbsp;&nbsp; REGISTER NOW &nbsp;&nbsp;&nbsp;</span>
    <span aria-hidden>REGISTER NOW &nbsp;&nbsp;&nbsp; REGISTER NOW &nbsp;&nbsp;&nbsp;</span>
  </div>
</div>
```

## Gotchas

### Courier Prime is NOT a Variable Font
Weight `'400'` and `'700'` must be explicitly listed. Omitting `weight` will cause a build error. Also load `italic` styles if the design uses italic variants (Figma often uses italic for Courier Prime accents).

### Instrument Serif is NOT a Variable Font
Only `'400'` weight exists. Load both `normal` and `italic` styles — the design may use italic for display text.

### Workbench Import Name
Import as `Workbench` (single word, no underscore needed). The font is available in `next/font/google`. If it fails to resolve at build time, check the exact export name by inspecting `node_modules/next/dist/compiled/@next/font/dist/google/font-data.json` — search for "Workbench".

### shadcn globals.css Conflict
The existing `globals.css` imports `shadcn/tailwind.css` and sets sidebar/chart/radius tokens. Do NOT delete the existing `@theme inline` block — extend it. Removing shadcn tokens breaks all shadcn components (accordion, etc.).

### Dark Mode Variables
The existing `globals.css` has a `.dark` block overriding colors. Since this design is light-only, override the `:root` values for `--background` and `--foreground` but leave the `.dark` block alone. Dark mode is out of scope and shadcn components may be used in the project for other purposes.

### Tailwind v4 Font Class Names
In Tailwind v4, defining `--font-mono` in `@theme inline` generates the `font-mono` utility class. Defining `--font-serif` generates `font-serif`. Defining `--font-display` generates `font-display`. These class names can then be used directly: `<h1 className="font-serif">`. This is the pattern shown in official Next.js+Tailwind docs for v4.

### No tailwind.config.js
This project uses Tailwind v4 which is CSS-configured. There is no `tailwind.config.js` and you should not create one. All theme extensions go in `globals.css`.
