# Codebase Structure

**Analysis Date:** 2026-03-07

## Directory Layout

```
myhack/                         # Project root
├── app/                        # Next.js App Router source (all routes live here)
│   ├── favicon.ico             # Browser tab icon
│   ├── globals.css             # Global styles, Tailwind import, CSS token definitions
│   ├── layout.tsx              # Root layout (wraps every page)
│   └── page.tsx                # Root route handler → renders at "/"
├── public/                     # Static assets served at URL root
│   ├── file.svg
│   ├── globe.svg
│   ├── next.svg
│   ├── vercel.svg
│   └── window.svg
├── .planning/                  # GSD planning documents (not deployed)
│   └── codebase/               # Auto-generated codebase analysis docs
├── eslint.config.mjs           # ESLint config (Next.js + TypeScript rules)
├── next-env.d.ts               # Auto-generated Next.js TypeScript declarations
├── next.config.ts              # Next.js framework configuration
├── package.json                # Dependencies and npm scripts
├── postcss.config.mjs          # PostCSS config (required by Tailwind v4)
└── tsconfig.json               # TypeScript compiler options
```

## Directory Purposes

**`app/`:**
- Purpose: All application source code. Routes are defined by file-system hierarchy under this directory.
- Contains: Page components (`page.tsx`), layout components (`layout.tsx`), route-level CSS, and the favicon
- Key files: `app/layout.tsx`, `app/page.tsx`, `app/globals.css`

**`public/`:**
- Purpose: Static files served verbatim at the web root. A file at `public/foo.svg` is accessible at `/foo.svg`.
- Contains: SVG assets only (all are Next.js/Vercel branding from the scaffold)
- Key files: `public/next.svg` (referenced in `app/page.tsx`)

**`.planning/codebase/`:**
- Purpose: GSD codebase analysis documents consumed by `/gsd:plan-phase` and `/gsd:execute-phase`
- Generated: Yes (by `/gsd:map-codebase`)
- Committed: Yes (serves as living documentation)

## Key File Locations

**Entry Points:**
- `app/layout.tsx`: Root layout - applied to every route; sets fonts and imports globals
- `app/page.tsx`: Root page - renders at `/`

**Configuration:**
- `next.config.ts`: Next.js build and runtime configuration
- `tsconfig.json`: TypeScript settings; defines `@/*` path alias resolving to project root
- `eslint.config.mjs`: Linting rules (Next.js core-web-vitals + TypeScript presets)
- `postcss.config.mjs`: PostCSS pipeline (required for Tailwind CSS v4)

**Styling:**
- `app/globals.css`: Global CSS entry point; imports Tailwind, defines `:root` CSS variables for background/foreground and font tokens

**Type Declarations:**
- `next-env.d.ts`: Auto-generated by Next.js; do not edit manually

## Naming Conventions

**Files:**
- Route files follow Next.js App Router reserved names: `page.tsx`, `layout.tsx`, `error.tsx`, `loading.tsx`, `not-found.tsx`
- CSS files: `globals.css` (kebab-case)
- Config files: `next.config.ts`, `eslint.config.mjs`, `postcss.config.mjs` (kebab-case with dots)

**Directories:**
- Route segments: lowercase, kebab-case (e.g., `about-us/` for the `/about-us` route)
- Special route groups: parentheses notation, e.g., `(auth)/` (not yet used)
- Dynamic segments: bracket notation, e.g., `[id]/` (not yet used)

**Components:**
- Default exports for page and layout files (required by Next.js)
- PascalCase function names matching the file's role (e.g., `RootLayout`, `Home`)

## Where to Add New Code

**New Page/Route:**
- Create `app/[route-segment]/page.tsx` with a default-exported React Server Component
- Example: `app/dashboard/page.tsx` → accessible at `/dashboard`

**New Shared Layout:**
- Create `app/[segment]/layout.tsx` to wrap a subtree of routes

**New Reusable Component:**
- Create `app/components/` directory (does not exist yet) and add component files there
- Or create a top-level `components/` directory at the project root for broader reuse
- Use `@/components/MyComponent` import path (the `@/*` alias resolves to project root)

**New API Route:**
- Create `app/api/[endpoint]/route.ts` exporting HTTP handler functions (`GET`, `POST`, etc.)

**New Utility / Helper:**
- Create `lib/` at the project root (does not exist yet) for shared logic
- Import with `@/lib/myHelper`

**New Static Asset:**
- Place in `public/` - will be served at `/{filename}` with no build processing

## Special Directories

**`.next/`:**
- Purpose: Next.js build output and dev server cache
- Generated: Yes (by `next build` or `next dev`)
- Committed: No (in `.gitignore`)

**`node_modules/`:**
- Purpose: Installed npm packages
- Generated: Yes (by `npm install`)
- Committed: No
